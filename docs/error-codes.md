> 适用范围：cosen 小程序端 `/app/**` 接口（会员、商品、券、订单、支付）。
> 后台管理端 `/system/**` 继续沿用 RuoYi 原有返回风格，不在本规范内。
> 状态：**全量 16 接口已冻结（v1.0.0，2026-11-16 站会评审通过）**——第一组（认证与会员 6 接口）、第二、三组（商品目录 3 接口 + 优惠券背包 2 接口）、第四组（订单与混合支付 5 接口）。

## 1. 编码规则

采用 5 位业务码，按 HTTP 语义分组，便于前端统一处理：

| 分组 | 范围 | 含义 |
|---|---|---|
| 400xx | 400 / 413 / 415 | 参数缺失、格式错误、取值非法、请求体过大、媒体类型不支持 |
| 401xx | 401 | 未登录、token 无效/过期、登录态异常 |
| 403xx | 403 | 越权、功能未启用、账号被限制 |
| 404xx | 404 | 资源不存在（商品、券、订单、会员等） |
| 409xx | 409 | 业务冲突/状态不允许（余额、券、库存、订单状态机） |
| 429xx | 429 | 限流、防刷 |
| 5xxxx | 500 / 502 / 503 | 服务端错误、依赖不可用 |

已存在的登录错误码保持不变：40101、40102、40103、40901、40902、42901。

重要约定：

- `/app/**` 返回**真实 HTTP 状态码**（401/403/404/409/429/500/503），body 内再带业务码；
- RuoYi 后台默认是「HTTP 200 + body.code」的老风格，两者分开，不要混用；
- 幂等类场景（重复下单、重复支付回调）**返回成功**，不设计成错误码。

## 2. 错误响应结构

```json
{
  "code": 40903,
  "msg": "余额不足",
  "data": null,
  "traceId": "c8f1d2e3a4b5"
}
```

- `code`：业务码（见下表）；
- `msg`：面向用户/前端的简短文案（可配置 i18n）；
- `data`：错误时固定为 null；
- `traceId`：服务端链路 ID，便于排查与客诉定位。

## 3. 错误码总表

### 3.1 参数 / 请求

| 码 | HTTP | 场景 | 前端处理 |
|---|---|---|---|
| 40001 | 400 | 必填参数缺失或为空 | 提示并阻止提交 |
| 40002 | 400 | 参数格式错误（JSON、数字、日期） | 提示参数不合法 |
| 40003 | 400 | 枚举或范围非法（payMode、status 等） | 提示并上报 |
| 40004 | 400 | 分页参数超限（pageSize 大于 100、pageNum 小于 1） | 回退默认值 |
| 40005 | 413 | 请求体过大 | 提示压缩或拆分 |
| 40006 | 415 | Content-Type 不支持 | 修正请求头 |

## 5. 按接口映射：GET /app/member/profile

接口：会员资料加可用余额（接口 ID 536879299）。

**必须设计的错误码：**

| 码 | HTTP | 触发条件 | 前端动作 |
|---|---|---|---|
| 40101 | 401 | 请求头没有 Authorization，或 token 查不到 | 清 token，走登录 |
| 40104 | 401 | token 已过期 | 静默续期或重新登录 |
| 40105 | 401 | 拿 admin token 调 /app 接口 | 清 token，走会员登录 |
| 40106 | 401 | token 已注销或被踢 | 重新登录 |
| 40405 | 404 | token 有效但会员记录已删除 | 清 token，重新登录 |
| 40901 | 409 | 会员被停用 | 提示联系门店 |
| 50001 | 500 | 服务端异常 | 提示稍后重试并上报 |
| 50302 | 503 | Redis 或 MySQL 不可用 | 提示稍后重试 |

**可选（按需）：**

| 码 | HTTP | 说明 |
|---|---|---|
| 42904 | 429 | 若 profile 接口配置了限流 |
| 40303 | 403 | 若账号风控状态在 profile 中也要拦截 |

**不需要的码：**

- 400xx：该接口没有请求参数，不存在参数校验失败；
- 40301 越权：接口不接收 memberId，只能读自己，不存在横向越权；
- 40401 至 40404、409xx 业务冲突：profile 只读，不涉及商品、券、订单、支付。

**响应脱敏建议：**

profile 返回的会员信息不要暴露 openid、unionid、手机号明文；建议返回：

| 字段 | 说明 |
|---|---|
| id | 会员 ID（string） |
| memberNo | 会员号 |
| nickname | 昵称 |
| avatarUrl | 头像 |
| level | 会员等级 |
| points | 积分 |
| balanceCent | 可用余额（分） |
| giftBalanceCent | 赠送余额（分） |
| phoneBound | 是否已绑定手机号（boolean） |
| phoneMasked | 脱敏手机号，如 138****0817 |

| 接口 | 保留 | 删除 / 不设计 | 理由 |
|---|---|---|---|

| GET /app/orders | 40101、40104、40105、40106、40002、40004、40405、40901、50001、50302 | 40001、40007、40301–40304、40401–40404/40406、409xx 业务冲突 | 只查本人订单，分页是唯一参数风险 |
| GET /app/orders/{orderNo} | 40101、40104、40105、40106、40404、40901、50001、50302 | 40001/40004/40007、40301、40401/40402/40403/40405/40406、409xx | 用 40404 同时表达“不存在/非本人”，防订单号枚举 |
| POST /app/orders/{orderNo}/pay | 40101、40104、40105、40106、40001、40002、40003、40921、40404、40901、40903、40916、40917、40919、40920、40922、40926、42902、50001、50002、50301、50302 | 40004/40007、40401/40403/40405/40406、40907–40915、40918、40923/40924、40925 | 40920/40921 是本接口专属；40926 走 HTTP 200 幂等成功 |
| POST /app/orders/{orderNo}/cancel | 40101、40104、40105、40106、40404、40901、40916、40918、50001、50302 | 40001/40004/40007、40301–40304、40401/40403/40405/40406、409xx 其余 | 取消是状态机操作，不动钱/券/库存 |

**三条已冻结语义**：

1. **幂等**：同 `Idempotency-Key` 同 payload 重复下单返回 HTTP 200 + `40925`（返回原订单，不算失败）；同 key 不同 payload 返回 `40007`，不新增 40927；重复支付回调返回 HTTP 200 + `40926`。
2. **重复取消**：`cancelled` 订单再次取消返回 HTTP 200 + 原订单（幂等）；`40918` 只用于 `completed` 订单，`40916` 用于 `paid/making/ready`。
3. **mixed 组合支付**：`balancePayCent > 0` 且 `wechatPayCent > 0` 且 `balancePayCent + wechatPayCent = payableCent`；两列有 0 或拆分不平分别返回 `40921`/`40920`，服务端按商品价重算不一致返回 `40919`。

## 6. 落地方式

1. Java：定义 `CosenErrorCode` 枚举（code、msg、httpStatus），`BizException` 抛出，`@RestControllerAdvice` 统一转换成上面的响应结构；
2. OpenAPI：新增 `ErrorResult` schema，每个接口补齐 400、401、403、404、409、429、500 响应示例；
3. Apifox：接口「文档 → 返回响应」为每个错误状态加示例，QA 用例直接引用这些示例做断言；
4. 前端：维护一张「code 到 文案和动作」的映射表（重登、重试、提示、联系门店），与本表「前端处理」列一致。

## 7. 注意事项

- RuoYi 后台异常默认返回 HTTP 200 加 body.code=500，`/app/**` 必须显式返回真实 HTTP 状态；
- 幂等重复下单、重复支付回调返回成功（200），否则前端会误报失败，微信会反复重试；
- 注销（logout）必须幂等：token 已过期或已注销时返回 200，不抛 40104/40106，否则前端会陷入重登循环；
- 券详情与券背包的“非本人券”一律返回 40403，不要用 40301，避免通过状态码枚举他人券号；
- 不要为尚未实现的场景预留大量错误码，评审时按「代码里是否真的会走到」逐条确认；
- 错误码一经冻结，只允许新增，不允许改变含义。
